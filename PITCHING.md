# Pitching Neuro

## Opening hook

**A brain MRI is a thousand-piece puzzle, and the tumor doesn’t come with the picture on the box. Neuro takes a first pass at finding and outlining it, so clinicians can spend less time tracing and more time deciding what matters.**

## The problem and the solution

Brain MRI contains a lot of detail, and outlining a tumor across multiple slices can take time and vary between readers. Neuro is a research prototype that analyzes MRI slices and creates a first-pass tumor-region outline for a clinician to inspect. It aims to make repetitive outlining faster and more consistent while keeping the specialist responsible for review and decisions.

## How it works

1. **MRI input:** The demo uses four MRI sequences: T1, T1ce, T2, and FLAIR.
2. **Slice analysis:** A 2D U-Net processes each slice and predicts a tumor-related class for each pixel.
3. **Mask generation:** The pixel predictions form a segmentation mask that can be displayed over the scan.
4. **Inference and display:** A FastAPI service runs the model; a React and Vite interface presents the scan and prediction overlay.
5. **Human review:** A clinician inspects the proposed outline and decides whether it needs correction. Neuro is an assistive prototype, not an autonomous diagnostic system.
6. **Evaluation:** Predictions are compared with expert-labeled BraTS examples. Dice score measures overlap between predicted and reference masks.

## Technology and model

- **Model:** 2D U-Net with four MRI input channels and four output classes.
- **Deep learning:** PyTorch 2.x and MONAI.
- **Training data:** BraTS 2020 slices, stored as HDF5 files, with expert-provided segmentation labels.
- **API:** FastAPI, served with Uvicorn.
- **Frontend:** React and Vite, using pnpm.
- **Environment and scripts:** Python 3.10–3.12, uv, and project scripts for training, evaluation, and demo export.

## Preventing unsupported claims

Neuro does not generate a free-form medical explanation. It outputs a segmentation mask from the image, which limits the kind of answer it can produce, but it does not prevent incorrect predictions. The project compares predictions with labeled examples using segmentation metrics, and the interface presents the result for human inspection. A prediction should be described as a model estimate or draft—not as a confirmed diagnosis. The project’s current small smoke-run result is not evidence of clinical readiness.

## Manual workflow and Neuro

| Manual outlining | Neuro-assisted prototype |
|---|---|
| A specialist draws the outline slice by slice. | The model produces a first-pass pixel mask. |
| The first outline can take considerable time. | The outline is generated by inference and shown in the interface. |
| Outlines can vary between readers. | The same trained model applies the same learned process to each input. |
| The specialist outlines and makes the clinical judgment. | The specialist reviews and corrects the draft, then makes the clinical judgment. |

The shared goal is to give the care team a useful tumor map to review. Neuro is designed to reduce repetitive drawing, not remove expert oversight or replace the wider clinical workflow.

## What makes the project distinctive

Neuro brings together a complete research-to-demo path: labeled MRI data, model training and evaluation, an inference API, and a browser interface for inspecting overlays. The useful feature to emphasize is the reviewable visual output: users can see where the model marked the scan and compare that result with the underlying image.

When presenting the built-in sample cases, clarify that their overlays are paired BraTS reference examples and display dataset labels; they are static examples, not live model predictions. Live predictions come from uploading a scan to the API.

## Challenges I faced

- **Limited compute:** The development workstation has no NVIDIA GPU, so the initial training setup had to be CPU-friendly and based on 2D slices.
- **Getting the data pipeline working:** BraTS data was downloaded as many HDF5 slice files. The project first used synthetic data as a smoke-test fixture, then connected the training and demo workflow to the real dataset.
- **Avoiding misleading demonstrations:** Many slices have no tumor in the labels, while tumor is more visible in other parts of the stack. Choosing representative clear and tumor-positive examples—and distinguishing ground-truth sample overlays from live predictions—takes care.
- **Keeping the result in scope:** A segmentation model can make mistakes, and a small smoke run does not establish clinical performance. The system must be presented as a prototype that needs more evaluation and human review.
- **Connecting research code to a usable demo:** The model needed to work through an API and a frontend, not only in a training script, so the project includes FastAPI inference and a React interface.

## Short spoken version

“A brain MRI is a thousand-piece puzzle, and the tumor doesn’t come with the picture on the box. Neuro uses a 2D U-Net trained on BraTS MRI slices to create a first-pass tumor outline, then shows it over the scan in a web app. I built the pipeline with PyTorch and MONAI, served predictions through FastAPI, and used React and Vite for the interface. The model can be wrong, so the outline is a draft for a specialist to review—not a diagnosis. One of my main challenges was building and demonstrating the pipeline on CPU while making sure sample labels weren’t confused with live model predictions.”
